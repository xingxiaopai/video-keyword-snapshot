# 批量视频关键字画面截图工具

扫描一批视频，按设定频率抽帧做 OCR 文字识别；**凡是画面中出现指定关键字的帧，自动截图保存**，
并输出 CSV / JSON 清单和一份可视化 HTML 报告。

典型场景：

- 直播回放里定位出现「下单」「优惠券」「抽奖」的画面
- 课程 / 会议录像里找某个术语、人名的出现位置
- 素材库排查：哪些视频里出现了竞品名称、品牌词
- 监控 / 录屏中检索特定告警文字

**30 秒上手**（在 `video-keyword-snapshot` 目录下执行）：

```bash
python run_interactive.py
```

按提示填视频路径和关键字即可。想看参数细节继续往下读。

## 一、安装

```bash
pip install -r requirements.txt
# 或者
pip install opencv-python numpy rapidocr-onnxruntime
```

- `rapidocr-onnxruntime` 自带中英文识别模型，**完全离线**，首次运行不需要下载。
- 可选：`pip install pyyaml`（用 YAML 配置文件时需要）。
- 可选：`pip install pytesseract` + 安装 Tesseract-OCR（想用 `--engine tesseract` 时）。

### 如果 `python` 不是装了依赖的那个解释器

有些环境里 `python` 指向一个干净的全局解释器，直接运行会报
`ModuleNotFoundError: No module named 'cv2'`。这时不用改脚本，任选一种方式告诉它用哪个：

| 方式 | 做法 | 适用 |
|---|---|---|
| 环境变量 | `set VKWS_PYTHON=D:\venvs\vks\Scripts\python.exe` | 临时 / 全局 |
| 配置文件 | 在项目目录新建 `.python-path`，里面写一行解释器完整路径 | 本项目长期使用 |
| 项目内虚拟环境 | 在项目目录建 `.venv`，即 `python -m venv .venv` 后装依赖 | 推荐，最标准 |

查找顺序是：`VKWS_PYTHON` → `.python-path` → `.venv\Scripts\python.exe` → `PATH` 里的 `python`。
其中 `.python-path` 和 `.venv` 都在 `.gitignore` 里，不会被提交到仓库。

## 二、快速开始

### 方式 A：双击运行（最简单）

直接**双击 `run.cmd`**，会启动交互式向导，按提示填路径和关键字即可。
也可以在终端里给它传参数，走命令行模式：

```
run.cmd -i "D:\videos" -k "优惠券,下单" -o "D:\out"
```

### 方式 B：交互式向导

```bash
python run_interactive.py
```

按提示依次填：视频路径 → 关键字 → 识别区域 → 输出目录 → 抽帧间隔。
路径可以直接把文件夹从资源管理器**拖进终端窗口**，会自动填入；粘贴时带的引号会自动去掉。
最后它会打印出**等价的命令行**，以后可以直接复制使用，不用再走一遍问答。

### 方式 C：命令行

```bash
# 1) 最简用法：处理一个目录下所有视频，找「优惠券」和「立即下单」
python video_keyword_snapshot.py -i "D:/videos" -k "优惠券,立即下单" -o "D:/out"

# 2) 只识别画面底部字幕区（更快更准，强烈推荐）
python video_keyword_snapshot.py -i "D:/videos" -k "抽奖" -o "D:/out" --roi "0,0.72,1,1"

# 3) 用配置文件批量跑
python video_keyword_snapshot.py -c config.yaml

# 4) 先看看会处理哪些视频（不识别）
python video_keyword_snapshot.py -i "D:/videos" -k x --dry-run
```

跑完后打开 `输出目录/report.html`，就是一份带缩略图、可按关键字/视频/文本筛选的截图报告。

### `-i` 路径支持的所有写法

| 写法 | 例子 |
|---|---|
| 单个文件 | `-i "D:/videos/a.mp4"` |
| 一个文件夹（默认递归子目录） | `-i "D:/videos"` |
| 通配符 | `-i "D:/videos/**/*.mp4"` |
| 多个路径（空格分隔） | `-i "D:/a" "E:/b"` |
| 多个路径（分号分隔） | `-i "D:/a;E:/b"` |

反斜杠和正斜杠都可以（`D:\videos` 与 `D:/videos` 等价），中文、空格路径都已兼容。
路径带空格时记得用双引号包起来。

## 三、工作原理

```
视频 → 按间隔抽帧 → 画面变化检测（跳过静止帧）→ OCR 识别文字
     → 关键字匹配 → 相邻命中合并成片段 → 每段挑最佳帧 → 截图 + 清单 + 报告
```

几个关键设计：

**1. 画面变化检测（默认开启，提速 3~10 倍）**
每个采样帧先和「上一次真正做过 OCR 的帧」比对变化像素占比。占比低于 `--scene-threshold`
（默认 0.002）就跳过 OCR，因为画面几乎没变、文字也不会变。这样静止画面、长时间不变的字幕
都只识别一次，且不会漏检——被跳过的帧与已识别帧内容几乎相同。
指定 `--roi` 后，变化检测只在 ROI 区域内进行，灵敏度更高。

**2. 文本规范化（默认开启，显著提升中文命中率）**
OCR 经常自行插入空格和标点，把「优惠券」识别成「优 惠 券」或「优惠券，」。程序在比对前会
做全角转半角、去掉空白和标点，所以这些情况都能命中。

**3. 整帧合并匹配（默认开启）**
关键字可能被 OCR 切成两个文本框（比如「立即」和「下单」分属两个框）。程序会把整帧文本
拼接后再匹配一次，避免漏检。

**4. 相邻命中合并**
间隔小于 `--merge-gap`（默认 2 秒）的命中视为同一段，默认只保存该段里"最好"的一帧，
避免同一句字幕生成几十张重复截图。想要全部帧用 `--save-mode all`。

## 四、常用参数

### 输入输出

| 参数 | 说明 |
|---|---|
| `-i, --input` | 视频文件 / 目录 / 通配符，可多个，也可用分号分隔。目录默认递归 |
| `-k, --keywords` | 关键字，多个用英文逗号分隔 |
| `-kf, --keyword-file` | 从文本文件读关键字（每行一个，`#` 开头为注释） |
| `-o, --output` | 输出目录，默认 `./output` |
| `-c, --config` | YAML 配置文件（命令行参数优先级更高） |
| `--flat` | 所有截图放同一目录（默认按视频分子文件夹） |
| `--no-recursive` | 不递归子目录 |

### 速度 / 精度（最常调的几个）

| 参数 | 默认 | 说明 |
|---|---|---|
| `--roi` | 无（整帧） | **最有效的优化**。只识别指定区域，相对坐标 `x1,y1,x2,y2`（0~1）。底部字幕用 `0,0.72,1,1`；多个区域用分号分隔 |
| `--interval` | `1.0` | 抽帧间隔秒数。关键字一闪而过就调到 `0.3`~`0.5` |
| `--scene-threshold` | `0.002` | 画面变化阈值，`0` = 关闭去重（最稳但最慢） |
| `--max-side` | `1600` | OCR 前把长边缩到此值内。调到 `960` 更快，画质差/小字多就调到 `1920` |
| `--min-score` | `0.5` | OCR 置信度下限，误识别多就调到 `0.7` |
| `--workers` | 自动 | 并行处理的视频数（默认 CPU 核数一半，上限 4） |

### 匹配方式

| 参数 | 说明 |
|---|---|
| `--regex` | 关键字按正则解释，如 `"下单|抽奖|立减\\d+元"` |
| `--case-sensitive` | 区分大小写（默认忽略） |
| `--no-normalize` | 关闭文本规范化（默认开启，不建议关） |
| `--fuzzy 0.85` | 模糊匹配，容忍 OCR 错字，0~1 越大越严格 |
| `--no-join-lines` | 关闭整帧合并匹配 |

### 截图策略

| 参数 | 默认 | 说明 |
|---|---|---|
| `--save-mode` | `best` | `best` 每段最佳帧 / `first` 每段首帧 / `all` 全部命中帧 |
| `--merge-gap` | `2.0` | 间隔小于此秒数的命中合并为同一段 |
| `--min-interval` | `0.0` | 两张截图之间的最小间隔，防止刷屏 |
| `--start` / `--end` | `0` | 只处理某个时间段 |
| `--draw-boxes` | 关 | 在截图上画出 OCR 文本框 |
| `--no-burn-text` | — | 不在截图上烧录时间戳和命中关键字 |
| `--image-format` | `png` | `png` 或 `jpg` |
| `--resume` | 关 | 断点续跑，跳过已完成的视频 |
| `--no-progress` | 关 | 不要动态进度条，改为每 30 秒一行进度日志 |
| `--quiet` | 关 | 完全静默，只输出结果汇总和错误 |

## 五、进度显示

运行时终端里会有一个实时刷新的面板，处理单个长视频时也能看到真实进度：

```
视频 1/3 个已完成 · 累计命中 7 张 · 已用 02:14
[██████████████░░░░░░░░░░]  58.3%  3m30s/6m00s  OCR 214 帧  命中 3 张  剩余 ~2m30s  直播回放_A.mp4
[█████░░░░░░░░░░░░░░░░░░░]  21.4%  1m17s/6m00s  OCR  76 帧  命中 1 张  剩余 ~4m42s  直播回放_B.mp4
```

每一列的含义：

| 显示 | 含义 |
|---|---|
| `视频 1/3 个已完成` | 整体进度：多少个视频已跑完 |
| `累计命中 7 张` | 所有已完成视频加起来的截图数 |
| `[███░░░] 58.3%` | 当前视频的进度（按视频时间轴算，不是按耗时） |
| `3m30s/6m00s` | 已经处理到视频的第 3 分 30 秒，总长 6 分钟 |
| `OCR 214 帧` | 实际做了文字识别的帧数（被画面去重跳过的帧不计入） |
| `命中 3 张` | 这个视频目前命中了几张 |
| `剩余 ~2m30s` | 预计还要多久；刚开始进度太低时显示 `--`（避免假数字） |

多进程并行时，每个正在处理的视频各占一行；某个视频跑完后那一行消失，上面的计数递增。

**输出被重定向到文件或管道时**（比如 `> log.txt`），会自动切换成日志模式，
每行一条记录、每个视频最多每 30 秒一条心跳，不会出现一堆控制字符：

```
  [开始] 直播回放_A.mp4  时长 1h02m  采样 3720 帧
  [███░░░]  21.4%  13m20s/1h02m  OCR 76 帧  命中 1 张  剩余 ~48m12s  直播回放_A.mp4
```

| 参数 | 效果 |
|---|---|
| 默认 | 终端里动态刷新进度条 |
| `--no-progress` | 不要动态进度条，改用每 30 秒一行的日志（适合记日志） |
| `--quiet` | 完全静默，只有最终汇总和错误信息 |

```

├── report.html              # 可视化报告（缩略图 + 关键字/视频/文本筛选 + 点击放大）
├── hits.csv                 # 截图清单（Excel 可直接打开）

    └── ...
```

截图文件名格式：`序号_时-分-秒_毫秒_命中关键字__视频文件名.png`，
文件本身也会在左上角烧录时间戳和命中的关键字。

`hits.csv` 字段：

| 字段 | 说明 |
|---|---|
| `video` / `video_path` | 视频文件名 / 完整路径 |
| `time_hms` / `time_sec` | 画面出现时间 |
| `keyword` | 命中的关键字 |
| `matched_text` | 命中的那一行识别原文 |
| `match_score` | 匹配相似度（精确命中为 1.0） |
| `ocr_score` | 该行 OCR 置信度 |
| `ocr_text` | 该帧识别到的全部文本（用 ` \| ` 分隔） |
| `image` / `image_name` | 截图路径 / 文件名 |

## 七、速度参考

单帧 OCR 耗时约 0.3~1.0 秒（CPU，取决于画面分辨率与文字量）。以 1 小时 1080p 视频为例：

| 配置 | 需要 OCR 的帧数 | 预估耗时 |
|---|---|---|
| 整帧 + 每秒 1 帧 + 关闭去重 | 3600 | 30~60 分钟 |
| 整帧 + 每秒 1 帧 + 开去重（默认） | 视画面变化，通常 100~600 | 2~8 分钟 |
| ROI 底部字幕 + 每秒 1 帧 + 开去重 | 通常 100~400 | 1~5 分钟 |

提速建议，按效果排序：**① 用 `--roi` 只识别字幕区 → ② 开画面去重（默认已开）
→ ③ 调小 `--max-side` → ④ 加大 `--workers`**。

## 八、配置文件

见 `config.example.yaml`，支持中英文键名（如 `输入` / `input`、`关键字` / `keywords`）。
命令行参数优先级高于配置文件。

```yaml
input:
  - "D:/videos/直播回放"
output: "D:/out/keyword_hits"
keywords: [优惠券, 立即下单, 抽奖]
interval: 1.0
roi: "0,0.72,1,1"
scene_threshold: 0.002
save_mode: best
workers: 0
resume: true
```

## 九、常见问题

**Q：中文路径的视频打不开？**
程序已内置兼容：打开失败时会自动把文件复制到 ASCII 临时目录重试。中文文件名、空格、
特殊字符都不影响。

**Q：某个关键字明明出现了却没截到？**
按顺序排查：① 用 `--scene-threshold 0` 关闭去重跑一遍，确认不是去重导致；
② 用 `--interval 0.3` 提高采样密度，确认关键字停留时间；③ 用 `--draw-boxes`
看 OCR 到底识别出了什么；④ 若 OCR 认错了字，用 `--fuzzy 0.8` 或 `--regex`；
⑤ 小字/低画质把 `--max-side` 调到 `1920` 或 `0`（不缩放）。

**Q：误识别太多，命中一堆无关画面？**
调高 `--min-score 0.7`，并用 `--roi` 限定区域；关键字尽量选长一点的词，避免用单字。

**Q：想用 GPU 加速？**
本工具默认走 `rapidocr-onnxruntime` 的 CPU 推理。要 GPU 可改装 `rapidocr-onnxruntime-gpu`
或用 `--engine tesseract` 配合支持 CUDA 的 Tesseract。另外，把 `--workers` 调大在多核
CPU 上通常比换 GPU 更省事。

**Q：支持音频里说出的关键字吗（语音识别）？**
不支持。本工具识别的是**画面上的文字**。若要按语音检索，需要 ASR（如 faster-whisper）
先转字幕，再按时间点去对应视频截图——这是另一条链路，不在本工具范围内。

**Q：视频是变帧率（VFR）的，时间戳准吗？**
时间戳按 `帧号 / FPS` 计算。VFR 视频可能有零点几秒的偏差；对定位用途足够，若要精确到帧，
建议先用 ffmpeg 转成固定帧率（`-vsync cfr`）再处理。

**Q：`--engine tesseract` 报错？**
需要先安装 Tesseract-OCR 本体并确保 `tesseract` 在 PATH 中，再 `pip install pytesseract`。
Windows 上还需指定语言包（中文需 `chi_sim`）。推荐直接用默认的 rapidocr。

## 十、退出码

| 码 | 含义 |
|---|---|
| `0` | 全部成功 |
| `1` | 没找到任何视频文件 |
| `2` | 参数或配置错误 |
| `3` | 部分视频处理失败（其余结果已正常输出） |
| `130` | 用户中断（Ctrl+C） |
